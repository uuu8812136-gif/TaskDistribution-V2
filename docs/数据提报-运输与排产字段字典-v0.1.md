# 数据提报：运输与排产字段字典 v0.1

## 1. 依据和读取方式

- 唯一字段依据：`references/提报类（开发）(3).xlsx`。
- 使用项目锁定的 SheetJS `0.20.3`，按 `raw: true` 读取单元格值、公式、合并区域和工作表 XML 中的 `dataValidation`。
- 本文只记录工作簿实际出现的字段和值。示例后带省略号的内容不当作完整字典。
- 与本次实现有关的 Sheet：`1.运输记录-主界面`、`1.运输记录-查询`、`1.运输记录-汇总报表`、`2.上月-日排产明细表`、`2.当月-日排产明细表`、`2.月排产明细表`。
- 上述 Sheet 的源文件没有 Excel `dataValidation`。封闭枚举仅采用备注明确列出的完整值。

## 2. 运输记录

### 2.1 固定录入字段

| 源字段 | API/模型字段 | 类型与服务端校验 | 来源说明 |
|---|---|---|---|
| 日期 | `reportDate` | `YYYY-MM-DD` 真实自然日期；默认取 `Asia/Shanghai` 当天 | 工作簿备注“默认日历当天” |
| 班次 | `shift` | 枚举：`白班`、`夜班`、`中班` | 工作簿明确列出完整值 |
| 车次 | `tripMasterId` + `tripLabel` | 必选；从当前团队启用的后台字典选择，文本为提交时快照 | 工作簿示例为“第1车/第2车/第3车...”，含省略号，不据此猜最大车次 |
| 路线 | `routeMasterId` + `route` | 必选；从当前团队启用的后台字典选择，文本为提交时快照 | 工作簿仅给“李福仓库-PC/李福仓库-总部/李福仓库-小义田...”等示例，不是完整白名单 |
| 出车类型 | `dispatchType` | 枚举：`配送`、`返架` | 工作簿明确列出完整值 |
| 车牌号 | `vehiclePlateMasterId` + `vehiclePlate` | 必选；从当前团队启用的后台字典选择，文本为提交时快照 | 工作簿提供了客户示例值；原值仅保存在忽略目录和本地测试库，不写入交付源码 |
| 车型 | `vehicleTypeMasterId` + `vehicleType` | 必选；从当前团队启用的后台字典选择，文本为提交时快照 | 主录入表没有该字段，但目标月汇总固定列包含“车型”；客户已确认由后台字典统一选择 |
| 姓名 | `driverMasterId` + `driverName` | 必选；从当前团队启用的后台字典选择，文本为提交时快照 | 工作簿提供了客户示例值；原值仅保存在忽略目录和本地测试库，不写入交付源码 |
| 现场照片 | `photoFileIds` | 仅接受 `FileAsset` ObjectId；同团队、未删除；完成接线后每车2-10张 | 不接受旧路径、URL或公开 `/uploads` 路径；小程序调用相机是客户端要求 |
| 备注 | `remark` | 0-2000 字符 | 查询结果固定列包含“备注” |
| 发车时间 | `submittedAt` | 服务端实际新增时间，不接受客户端覆盖 | 查询表备注“取提交的实际时间” |

车次、路线、车牌、车型和司机均属于“后台维护后选择”。Web和小程序提交时必须同时提供当前团队内启用的主数据 ID；服务端读取主数据并保存文本快照，不接受客户端以自由文本替代选择。主数据后续改名不追改历史单据。

### 2.3 查询和月汇总

- 查询条件：部门、运输日期、车牌号、司机姓名、运输路线、运输班次、运输车次、出车类型；支持多个条件并列。
- 列表固定列：序号、部门、运输日期、运输班次、运输车次、运输路线、出车类型、车牌号、姓名、装载明细合计、发车时间、详情、备注。
- 月汇总按`司机 + 路线`分组；每位司机下按`车牌 + 车型`列车，并为每辆车固定输出“配送/返架”两行；每位司机后输出小计。
- 月汇总按自然月实际天数输出每日趟数及趟数合计。源模板公式有漏算31日的单元格，系统不复制该错误。
- Excel固定包含公司标题、月份和部门副标题、星期/日期双层表头、绿色底色、边框、蓝色表头、筛选、冻结窗格及横向打印设置。

## 3. 排产

### 3.1 上月/当月日排产

上月和当月 Sheet 的列完全相同。模型按真实月份保存一份数据，“上月”和“当月”是基于`Asia/Shanghai`业务日派生的查询槽位，避免月份流转后产生两份冲突数据。

| 源字段 | 日明细字段 | 类型与校验 |
|---|---|---|
| 日期 | `dailyEntries[].date` | `YYYY-MM-DD`真实自然日期，必须属于记录的`month` |
| A线（白班） | `dailyEntries[].aLineDay` | 非负整数或空 |
| A线（夜班） | `dailyEntries[].aLineNight` | 非负整数或空 |
| 北线 | `dailyEntries[].northLine` | 非负整数或空 |
| 分动器线（分动器、飞轮壳总成、飞轮取力器、电动箱、扭转减震器） | `dailyEntries[].transferCaseLine` | 非负整数或空 |
| B线（白班） | `dailyEntries[].bLineDay` | 非负整数或空 |
| B线（夜班） | `dailyEntries[].bLineNight` | 非负整数或空 |
| 合计 | 响应派生值`total` | 服务端按六项之和计算，不接受客户端输入 |
| 本月生产计划（预测） | `productionPlanForecast` | 非负整数或空；每月一份 |

### 3.2 月排产

| 源字段 | 月字段 | 类型与校验 |
|---|---|---|
| 日期 | `month` | `YYYY-MM`真实自然月份 |
| A线 | `monthlyTotals.aLine` | 非负整数或空 |
| 北线 | `monthlyTotals.northLine` | 非负整数或空 |
| 分动器线（分动器、飞轮壳总成、飞轮取力器、电动箱、扭转减震器） | `monthlyTotals.transferCaseLine` | 非负整数或空 |
| B线（白） | `monthlyTotals.bLineDay` | 非负整数或空 |
| B线（夜） | `monthlyTotals.bLineNight` | 非负整数或空 |
| 合计 | 响应派生值`total` | 服务端按五项之和计算，不接受客户端输入 |

## 4. 隔离、权限和导出约束

- 所有运输与排产记录强制包含`teamId`和`orgUnitId`；`teamId`只取认证上下文。
- `ORG_UNIT`范围强制当前分部；`TEAM`范围可查看团队内分部并在写入时指定同团队分部；超级管理员全局模式只能读取，且必须明确`teamId`。
- 运输读取/写入/导出分别使用`report.view`、`report.submit`、`report.export`。
- 排产读取/写入/导出分别使用`report.view`、`report.schedule.manage`、`report.export`；不扩充一期固定权限键集合。
- 导出前重新执行团队和分部过滤。所有以`= + - @`开头的用户文本在Excel中加单引号，避免公式注入。
- 新增和修改同时写入不可变`ReportChangeRecord`和`AuditLog`；导出写入`AuditLog`。

## 5. 已挂载的 API

当前 V2 隔离开发副本已挂载：

```js
app.use('/api/transport-records', require('./routes/transportRecords'));
app.use('/api/production-schedules', require('./routes/productionSchedules'));
```

- `GET/POST /api/transport-records`：列表、新增。
- `GET/PATCH /api/transport-records/:transportRecordId`：详情、修改。
- `GET /api/transport-records/export?month=YYYY-MM`：固定月度司机趟数表。
- `GET/PUT /api/production-schedules/daily/:slot`：`:slot`仅为`previous`或`current`。
- `GET /api/production-schedules/daily/:slot/export`：固定日排产表。
- `GET /api/production-schedules/monthly`、`PUT /api/production-schedules/monthly/:month`：月排产查询和幂等维护。
- `GET /api/production-schedules/monthly/export`：固定月排产表。
