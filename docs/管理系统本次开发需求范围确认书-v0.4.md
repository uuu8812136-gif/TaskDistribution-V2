## 一、项目范围

本项目在现有网站和微信小程序上升级。保留现有任务管理模块，新增**设备管理模块**和**数据提报模块**。系统最终包含任务管理、设备管理、数据提报三个业务模块。

系统增加“项目团队”层级，例如“变速箱物流部”“发动机物流部”。不同团队共用系统，但任务、设备、提报、人员、消息、附件、照片、查询、统计、导出和审计记录完全隔离。

## 二、账号、组织和数据权限

| 项目 | 确认规则 |
|---|---|
| 超级管理员 | 可跨团队查看；全局状态默认只读，进入具体团队后才能修改。团队切换和关键修改记录审计日志。 |
| 普通管理员（项目管理员） | 只能进入所属团队；管理本团队普通成员的状态、组织和固定权限，不能访问其他团队，也不能自行提升项目管理员。 |
| 用户名 | 全系统唯一。上线前由客户指定首个超级管理员并首次登录改密，其余人员由客户配置。 |
| 组织层级 | 一级部门经理；二级部门副经理或部门经理助理；三级分部经理或分部副经理；四级班组长；末级普通员工。 |
| 分部级数据 | 普通员工、班组长、分部经理/副经理只查看本人所属分部的数据。 |
| 部门级数据 | 部门资产管理员、部门经理助理、部门副经理、部门经理查看整个部门7个分部的业务数据；部门考勤员处理7个分部的出勤提报。 |
| 固定权限 | 使用系统预设权限项勾选，不开发由客户任意创建角色、权限节点或数据范围的复杂权限平台。 |

现有用户、任务、审核、延期、消息、附件/文件及关联记录暂全部归入“变速箱物流部”，正式迁移前再书面确认一次。

## 三、数据提报模块

本次按《提报类（开发）(3).xlsx》的固定字段和固定样式开发，包含：

- 运输/运营记录、查询、月度司机趟数汇总和Excel导出。
- 7个分部的出勤提报、部门出勤汇总及生产日报文字生成。
- 上月日排产、当月日排产和月排产的PC端维护。
- 新增“出勤月报-部门汇总”，按所选月份从已经提交的每日出勤数据自动汇总并导出。

### 出勤提报规则

1. 7个分部分别指定1个提报账号，该账号只提报所属分部。
2. 09:00前，分部提报人可重复提交并覆盖本分部上一版数据。
3. 09:00后，分部提报人锁定；部门考勤员具有7个分部的补报或修改权限，所有修改保留原因、前后值和操作日志。
4. 7个分部未全部提交时，禁止生成当日汇总，并提醒缺报分部的指定提报人和部门考勤员。
5. 数据提交后由部门考勤员审核，审核完成后推送给部门经理。

### 生产日报计算规则

客户已确认：“昨日实际完成量”直接取昨日生产日报第3项“今日排产XX台”，即按排产计划作为实际完成量。系统按此业务口径计算，不再另设实际完成量填报入口。

## 四、设备管理模块

本次确认包含：

- 设备台账、照片、查询、Excel导入导出。
- 一物一码、二维码生成和小程序扫码查看。
- 设备盘点批次、盘点结果及差异处理。
- 点检功能，具体检查项目、周期、照片和提醒规则待补充。
- 维修功能，具体固定处理步骤待补充。
- 保养功能，具体周期、到期/逾期提醒和记录步骤待补充。
- 闲置、停用、报废申请及审批。

本次明确**不包含设备领用调拨**，也不包含设备配件、配件库存、仓库、采购及成本核算。

盘点采用四级固定审批：**盘点人提交 → 分部经理审核 → 部门副经理审核 → 部门经理审核**。该流程为固定审批，不扩展成可任意设计流程的平台。

客户现有固定资产台账和照片全部纳入迁移范围。当前初步识别约144条记录、约203个媒体文件，最终以双方封存文件为准。首次导入后生成异常清单；本次包含一轮客户确认及一次按确认结果修正导入，额外轮次按需求变更处理。

## 六、交付及验收边界

交付包括：现有任务模块团队化；上述设备和数据提报功能；组织层级、固定权限、数据范围和审计；历史业务数据迁移；设备台账、照片及异常清单；按最终确认的PC端和小程序页面清单交付；上线前备份、部署和基础使用说明。

除非补充进最终确认书，本次不包含：设备领用调拨、配件库存、自由配置角色/表单/审批流、定位打卡、排班或考勤机对接、高级统计大屏、任意自定义报表、第三方系统接口、无限次人工数据清洗及本次完成后的新增模板。

验收时必须满足：团队间数据完全隔离；各岗位数据范围正确；09:00锁定、缺报提醒、审核和推送按规则运行；月报能够从日数据生成；原任务数据和流程无明显回归；设备导入可对账；二维码、盘点四级审批、点检、维修、保养及状态审批符合最终固定流程。

最终确认后新增模块、页面、字段、模板、计算口径、审批层级、流程或第三方接口，均按需求变更另行确认费用和工期。
