# 客户基础操作说明

本说明面向系统管理员、项目管理员和日常业务用户。菜单是否显示由账号所在团队、组织、固定岗位和权限决定；看不到某个入口时，不应借用他人账号，应联系管理员核对授权。

## 1. 登录与团队

1. 打开管理员提供的 Web HTTPS 地址，或进入已发布的微信小程序。
2. 输入个人账号和密码；不得共用账号或在聊天中发送密码。
3. 有多个团队权限时选择当前业务团队。
4. 超级管理员处于“全局只读”时可以跨团队查询，但不能直接修改业务数据；需要操作时先进入指定团队。
5. 团队切换后重新核对页面顶部团队名称，再创建、审批或导出。
6. 使用完毕后退出登录；发现异常登录或权限变化立即联系管理员。

## 2. 消息与待办

- 进入“消息中心”查看任务、点检、保养、盘点、维修、审批和报表提醒。
- 打开消息后确认关联团队、设备/任务编号和当前状态，再进入详情处理。
- 不重复点击已成功提交的操作；网络异常时先返回列表刷新状态。
- 超期、异常或审批退回应按消息详情中的当前处理阶段办理。

## 3. 任务管理

### 创建与分派

1. 有 `task.create` 权限的用户进入“任务管理 > 创建任务”。
2. 填写标题、来源、说明、开始/计划完成时间、执行人、主负责人、抄送人和附件。
3. 团队任务和子任务要确认负责人及父任务关系。
4. 提交后在任务详情核对编号、人员和状态。

### 执行、延期与审核

1. 执行人从“我的任务”打开任务并按要求完成工作、填写结果和上传附件。
2. 需要延期时由允许的主负责人提交原因和天数；是否生效以审批结果为准。
3. 抄送/审核人员按页面状态完成审核或评价。
4. 管理人员最终确认后任务进入终态；不要通过重复提交绕过流程。

## 4. 设备台账与二维码

- Web“设备管理”用于按设备编号、名称、类别、组织和状态查询，并查看原始字段、照片和数据质量提示。
- 二维码应从该设备详情生成或下载，打印后先用体验环境验证可识别性，再用于现场。
- 小程序“设备扫码”只扫描系统生成的设备码。无效码、取消扫码、跨团队设备或无权限会显示对应提示。
- 设备资料或照片显示异常时记录设备编号和页面时间，不要创建重复设备规避问题。

## 5. 点检与保养

### 管理人员

1. 在 Web“设备规则”维护点检/保养项目、顺序、周期、执行窗口、照片和定位策略。
2. 启用规则前复核适用设备、周期和首个执行日期。
3. 在“点检保养工作台”按设备、组织、计划状态、执行结果和异常状态查询。
4. 异常按班组长、分部经理、设备管理员等页面显示阶段处理；填写处理意见后再提交。

### 现场执行人员

1. 扫描设备码或从设备详情进入“点检”/“保养”。
2. 逐项选择结果；异常项填写说明。
3. 页面要求照片时必须现场调用相机。水印图片生成失败时不会上传原图，应重新拍摄或报告管理员。
4. 根据授权结果确认日期、时间、地点或定位状态水印清晰可见。
5. 提交后返回设备详情，确认本自然月记录和计划状态已刷新。

## 6. 盘点、维修和设备状态申请

### 盘点

1. 管理人员在 Web 创建盘点批次和范围。
2. 现场人员扫码核对账实，差异项按要求填写说明和证据。
3. 提交后按固定审批链处理；退回时只修改允许字段并重新提交。
4. 终态批次不可继续编辑，导出前先核对批次范围和状态。

### 维修

- 根据实际情况选择故障报修、需换件维修或不换件维修。
- 现场照片数量和配件明细按页面要求填写；配件价格以服务端重新计算结果为准。
- 接单、维修、验收、审批、驳回和作废必须按当前状态执行。
- 本模块记录维修单中的配件，不代表仓库库存或采购台账。

### 闲置、停用、报废

- 只有设备管理员可发起申请。
- 选择正确申请类型，填写原因并附所需证据。
- 经助理/副经理和经理固定审批后，系统才更新设备正式状态。
- 不通过普通设备编辑绕过审批修改正式状态。

## 7. 运输、排产、出勤和日报

### 运输与排产

- 运输提报按日期、班次、派送类型、驾驶员、车辆和固定装载字段填写。
- 附件必须上传到当前记录，不用公共链接代替。
- 排产按自然月维护；导出前核对月份、团队和组织筛选。

### 出勤

1. 每个分部由当前有效提报人在当天截止时间前提交或替换。
2. 09:00 后的修改由考勤员填写原因，系统保留前后值审计。
3. 七个分部未齐时不能完成最终审核；根据缺报提示通知对应提报人。
4. 最终审核后日报永久锁定并生成可复制文字。
5. 月报只汇总已审核日报，导出前核对自然月和缺失日期。

### 生产日报

- 选择日期后查看当前/前期出勤和生产来源快照。
- 实际完成量按系统规则引用上一自然日排产数据；跨月时特别核对来源日期。
- 复制最终文字前确认版本、来源指纹和缺失数据提示。

## 8. 审计查询

- 审计页面只提供列表和详情查询，不提供修改、删除或导出。
- 全局审计仅超级管理员可查看；团队内还要求相应管理员身份和 `audit.view` 权限。
- 可按时间、人员、团队、资源、动作和业务编号筛选。
- 系统维护账号身份会被脱敏；不要尝试从审计快照恢复敏感信息。
- 调查问题时记录审计记录 ID、业务编号、时间和筛选条件，不截取无关人员数据。

## 9. 管理员日常检查

每天至少检查：

1. API/Web 健康状态和最近错误日志。
2. 最近一次成功备份时间、`backupId` 和校验状态。
3. 备份盘与上传盘剩余空间。
4. 点检/保养 worker、异常提醒和消息是否按配置运行。
5. 待审批、缺报、逾期和异常记录。

备份、恢复、计划任务和健康终端操作见 `docs/OPERATIONS_RUNBOOK.md`。发布和回滚见 `docs/RELEASE_DEPLOYMENT_AND_ROLLBACK.md`。

## 10. 问题反馈模板

反馈时提供以下非敏感信息：

- 发生时间和使用端（Web/微信小程序）；
- 当前团队、页面名称和业务编号；
- 操作步骤、预期结果和实际提示；
- 脱敏截图；
- 是否可重复、是否影响其他用户。

不得提供密码、JWT、环境文件、MongoDB URI、客户原始表格、完整人员名单或未脱敏附件。
