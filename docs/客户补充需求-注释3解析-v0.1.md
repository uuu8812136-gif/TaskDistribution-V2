## 2. 数据提报与考勤确认

1. 生产日报“昨日实际完成量”取前一日生产日报第 3 项“今日排产 XX 台”，即当前规则明确把排产计划作为次日的实际完成量。
2. 七个分部分别配置一个指定提报人；另配置一个部门考勤员，部门考勤员可处理七个分部的补报、修改和审核。
3. 七个分部未全部提交时禁止生成部门汇总，并提醒对应缺报分部的指定提报人和部门考勤员。
4. 09:00 后普通分部提报人锁定；部门考勤员在点击“审核确认”前仍可补报或修改。
5. 部门考勤员审核确认后数据永久锁定，不再支持退回、重开或继续修改。
6. 审核完成后只通知部门经理查看，不需要部门经理再次审批；小程序需要支持复制最终汇总文字。
7. 月报不单列“病假”，病假合并计入“请假”。

## 3. 组织岗位与数据范围

客户确认的岗位层级为：

1. 部门经理。
2. 部门副经理或部门经理助理。
3. 分部经理或分部副经理。
4. 班组长。
5. 普通员工。

数据范围固定如下：

- 普通员工、班组长、分部经理及分部副经理只能查看分配给本人或本人分部的数据。
- 部门资产管理员、部门经理助理、部门副经理和部门经理可查看整个部门七个分部的数据。
- 部门考勤员的七分部权限只用于考勤提报，不自动扩展到其他业务模块。

## 4. 设备功能范围

本次设备范围包含台账、照片、查询、导入导出、一物一码、扫码查看、盘点批次及差异、点检、维修、保养、闲置/停用/报废审批。明确不做设备领用调拨。

### 4.1 设备盘点

- 固定四级流程：盘点人提交 -> 分部经理审核 -> 部门副经理或部门经理助理审核 -> 部门经理最终审核。
- 部门经理助理可以替代部门副经理完成同级审批。
- 审批、退回、差异和签署意见必须保留审计记录。

### 4.2 设备点检

- 扫描设备二维码后进入设备现场页面，按当前设备类型动态展示适用的点检、保养和维修入口，不写死日点检、周点检、月点检等固定模板。
- 点检规则按设备类型配置；部门设备管理员及部门经理可自行新增、删除、排序点检项并维护执行要求，其他岗位不可维护规则。
- 周期规则支持手动发起、每 N 天/周/月、每 N 运行小时，以及日历周期与运行小时组合触发；日点检、周点检、月点检和专项点检只是可配置示例，不是固定枚举。
- 同一规则配置多个触发条件时可选择“任一条件先到（ANY）”或“全部条件达到（ALL）”，默认使用 ANY。
- 班前日点检可配置白班 07:00-09:00、夜班 19:00-21:00；每周一、每月 1 日均作为默认配置值而非代码常量。
- 点检项逐项选择正常或异常；异常必须填写说明并现场拍照。
- 异常提交后依次流转：设备操作者 -> 班组长处理 -> 分部经理处理 -> 部门设备管理员处理。只有上一级无法处理时才继续升级。
- 超过计划结束时间未点检时先提醒员工并通知所属分部经理；再超时 1 小时通知部门设备管理员和部门经理。周点检、月点检使用同类升级规则。
- 小程序拍照应优先限制为现场相机，不允许从相册选择；照片需要日期、时间和地点水印。实现时需按微信能力和用户授权处理定位不可用场景。
- PC 端需支持按设备、日期、组织和异常状态查询、导出全部点检记录；扫码稽查页默认展示当月点检、保养和维修情况。

### 4.3 设备维修

维修分为三类：故障报修、需更换配件维修、不需换件维修。

#### 故障报修

1. 扫码自动带出部门、分部、设备名称和设备编码。
2. 人工填写报修时间、地点、车牌、联系人、联系电话和故障描述，并现场上传 1-5 张照片。
3. 提交后由所属分部经理审核，随后推送部门设备管理员。
4. 部门设备管理员点击“确认报修接单”后，本段报修流程结束。

#### 需更换配件维修

1. 自动带出设备归属信息，人工填写维修日期、维修人和可动态增行的配件明细。
2. 分部经理进行维修结果验收，可修正提报信息。
3. 部门设备管理员逐行填写配件单价、数量和金额，并确认配件明细及价格。
4. 部门副经理或部门经理助理签署意见并审批，部门经理最终签署意见并审核。
5. 任一审批环节支持驳回创建人、驳回上一级或流程作废，全部操作写入审计日志。

#### 不需换件维修

- 自动带出设备归属信息，人工填写维修日期和维修人。
- 后续验收和审批链与需更换配件维修相同，但不包含配件明细及价格环节。
- 所有维修记录需支持查询和导出。

### 4.4 设备保养

- 设备类型、保养项目、周期和提醒规则均由部门设备管理员或部门经理维护，不写死在代码中。
- 保养与点检共用可扩展周期表达，支持手动、每 N 天/周/月、每 N 运行小时以及 ANY/ALL 组合规则；例如电机可配置为每运行 200 小时检查磨损。
- 规则修改仅影响后续执行，历史记录必须保存当时的规则版本和检查项快照。
- 逾期 1 天通知所属分部经理，逾期 2 天通知部门设备管理员，逾期 3 天通知部门副经理或经理助理以及部门经理。
- 执行保养必须上传现场水印照片；完成后自动计算并生成下一保养周期。
- 保养记录需支持查询、导出和异常筛选。

### 4.5 闲置、停用和报废

- 仅部门设备管理员可以发起。
- 固定审批链：部门设备管理员发起 -> 部门副经理或部门经理助理审核 -> 部门经理最终审批。
- 三类申请共用同一状态机，通过申请类型区分闲置、停用和报废。
- 正式设备状态只能在最终审批通过后变更。

## 5. 与当前测试版本的差异

当前隔离测试版本已经实现：

- 多团队、五级组织、固定岗位权限、团队间数据隔离和审计基础。
- 设备台账、分类、照片/附件、导入预览与异常确认、导出、详情、变更历史和二维码。
- 运输提报、司机月汇总、日排产和月排产。
- 任务模块的团队/组织数据范围适配。

以下内容尚未在当前测试版本实现，不能按现有页面视为已交付：

- 出勤日报、09:00 锁定、七分部完整性检查、部门考勤员审核和月报。
- 设备盘点批次、差异及四级审批。
- 日/周/月/专项点检、异常升级和超时提醒。
- 三类维修流程及配件价格审批。
- 动态保养规则、周期计算和多级逾期提醒。
- 闲置、停用和报废申请审批。

## 6. 仍需客户补充或最终确认

1. 首批点检/保养内容文件尚未收到，但不再阻塞功能开发；系统先交付可配置规则，客户后续可按设备类型自行录入或再提供文件批量初始化。
2. 需要七个分部、班组、员工、班组长、分部经理、设备管理员和部门管理层的组织关系表，才能配置异常升级和审批人匹配。
3. 需要确认 PC 端和小程序端的最终页面分工。建议小程序负责扫码、现场填报、拍照、处理和审批；PC 端负责模板、台账、查询、批量导出和管理配置。
4. “推送”需要确认使用系统站内消息、微信订阅消息或两者同时使用；微信订阅消息需要模板和用户授权。
5. 夜班点检窗口按白班规则平移为 19:00-21:00，二次升级时间为 22:00。该推导需客户最终确认。
6. 水印地点的精度、无法取得定位时是否允许提交，以及定位权限拒绝后的处理规则需要确认。
